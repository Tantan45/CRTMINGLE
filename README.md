# CRTMINGLE

Anonymous, text-only 1-on-1 chat for CRT students. There are no student accounts, logins, passwords, or email collection. Clicking **Start chatting** creates a secure anonymous session; matching stays subject to the Rules popup, moderation, and operating hours.

## Style guide

- White `#FFFFFF` cards and light-grey `#F5F7FA` sections.
- CRT blue `#0B4DA2` actions and links, with readable gold `#806500` highlights.
- Dark text `#1A1F2B`, hint text `#6B7280`, Inter/system sans-serif.
- 8px spacing scale, rounded cards, thin borders, soft shadows, pill interest chips.
- Light theme only; responsive layouts for phone, tablet, and desktop.

## Setup

1. Install Node.js 20 or newer and run `npm install` in this folder.
2. Copy `.env.example` to `.env`.
3. Set `SESSION_SECRET` and `FINGERPRINT_SECRET` to separate random values of at least 32 characters.
4. Choose a separate staff portal code of at least 14 characters. With `SESSION_SECRET` already set in `.env`, run `npm run admin:hash -- "your-staff-code"` and copy the result into `ADMIN_ACCESS_CODE_HASH`.
5. Configure `COUNSELOR_CONTACT`, `CRISIS_RESOURCE`, chat hours, timezone, and any extra `BLOCKED_TERMS`.
6. Run `npm run build`, then `npm run dev`. Open `http://localhost:3000` and select **Start chatting**, accept the Rules popup, choose an optional nickname and interests, then start a chat.
7. Open `http://localhost:3000/admin` and enter the staff access code to review reports and manage session bans.

For two-person local matching, use two different devices or network/browser fingerprints. The matcher deliberately will not pair identical anonymous session IDs or hashed fingerprints.

## Privacy and moderation

The app stores an anonymous session ID, an HMAC hash of the request IP, browser agent, and random browser token, messages, reports, blocks, bans, settings, and admin audit actions. The raw IP address is not stored by the app. Messages and moderation logs are deleted after 30 days. An active ban fingerprint remains until the ban expires.

Messages are text-only, filtered server-side, and rate-limited to five per ten seconds per fingerprint. Reports link the reported session and fingerprint to the last 20 messages from that chat. Three distinct fingerprint reports in the configured window trigger a 24-hour session and fingerprint suspension. Matching excludes blocked/reported session and fingerprint pairs, and excludes self-matches across tabs/devices with the same fingerprint.

## Admin Portal

Staff can review reports and chat context, dismiss reports, warn/suspend/ban/unban by session ID, report, or fingerprint, edit blocked words and operating hours, adjust report thresholds, view live counts, and inspect the audit log. Admin access uses a separate access code hash in `.env`.

## Deployment

On Render, Railway, or another Node host, use `npm install` and `npm run build` as build steps and `npm start` as the start command. Set `NODE_ENV=production`, configure all `.env` values as host secrets, serve over HTTPS, and mount persistent storage for `./data`. Set `TRUST_PROXY=true` only when the host's proxy headers are trusted. Keep one app instance for SQLite and in-memory Socket.IO matching; use PostgreSQL and shared real-time state before scaling to multiple instances.

## Five main risks and controls

1. **Harassment or unsafe behavior:** required student affirmation, rules, filters, report/block, session and fingerprint bans, staff review, and school contacts.
2. **Unverified visitors:** with instant anonymous access, the service cannot prove school enrollment. The Rules popup asks users to confirm CRT status; moderators can review reports and suspend sessions or fingerprints.
3. **Fingerprint limits:** the HMAC fingerprint is pseudonymous and helps deter cookie resets; IP changes, shared networks, or browser changes can weaken it. Moderators can also ban session IDs and review patterns.
4. **Sensitive chat logs:** admin-only review, clear logging notice, 30-day deletion, and no raw IP storage. Protect database disks and backups.
5. **False reports or filter misses:** threshold settings, moderator review, dismiss/warn actions, and editable filters help correct mistakes. Automation does not replace school safeguarding staff.

Have CRT approve the rules, privacy notice, counselor contact, moderation coverage, and retention policy before opening the service to students.
